# orchestration 팩 — 대규모 병렬 서브에이전트 오케스트레이션

**언제 넣나**: 서브에이전트 여러 개를 병렬로 돌려 대량 구현(수백 파일 콘텐츠 저작, 반복 배선, 다중 모듈 동시 작업)을 하는 **규모 있는 프로젝트**. 소규모·1인 프로젝트는 코어 §6(토큰 경제)의 위임 4규약으로 충분하다 — 이 팩은 넣지 마라.

> v1에서는 이 내용이 코어 CLAUDE.md §0에 기본 내장이었다. v2에서 팩으로 강등한 이유: 고정 파이프라인·8요소 브리프 강제는 병렬 규모가 있을 때만 이득이고, 소규모에서는 강한 모델의 판단을 절차로 깎는 비용만 남는다.

## 내용물

| 파일 | 용도 | 설치 위치 |
|---|---|---|
| `agent-brief-template.md` | 위임 브리프 8요소 정본 (병렬 안전의 핵심) | `docs/agent-brief-template.md` |
| `agents-team-README.md` | 에이전트 팀 협응 규칙 — 별명 매핑·소유 경계표·공유 순차 파일·핸드오프 | `.claude/agents/README.md` |
| `agent-template.md` | 서브에이전트 정의 파일 원본 템플릿 | `docs/templates/agent-template.md` |

## 설치

1. 위 표대로 파일을 프로젝트 정위치로 복사.
2. CLAUDE.md §6(토큰 경제) 끝에 아래 절을 추가:

```markdown
### 병렬 오케스트레이션 (orchestration 팩)

- 에이전트 위임 시 `docs/agent-brief-template.md`의 **8요소 브리프** 필수 — 요약하지 말고 템플릿 복붙 + 델타만.
- 소유 경계·순차 파일·핸드오프 = `.claude/agents/README.md`가 정본. 서로 다른 파일만 만지면 병렬, 공유 파일은 순차.
- 에이전트가 중간에 죽으면: 남긴 파일을 `git status`로 확인 → "기존 산출물 검수부터"를 지시하는 이어받기 에이전트 재가동.
- 모델 배정: 설계·검수·승인 = 최상위 모델 / 대량 저작·배선 = 중간 모델 / 커밋·최종 판단 = 메인.
```

3. `.claude/agents/README.md`의 경계표를 실제 파일 구조로 채운다.

## 제거

설치한 3개 파일 삭제 + CLAUDE.md의 "병렬 오케스트레이션" 절 삭제.
