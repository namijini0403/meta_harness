# risk-review — 고위험 변경의 독립 검증 (Veriloop-lite)

**목적**: 구현자가 자기 작업을 자기 논리로 승인하는 A=A 함정을 깨고, 구현자가 예상하지 못한 시험으로 과적합을 잡는다.
**비용**: 서브에이전트 1~2개. 그래서 위험 구역 전용이다.

## 절차

### 1. 동결 (freeze)
- 검증 대상을 고정한다: `git rev-parse HEAD` + `git diff [--staged]` 범위를 기록.
- 동결 이후 대상이 바뀌면 검증은 무효 — 처음부터 다시.

### 2. 블라인드 리뷰어 (신선한 컨텍스트 서브에이전트 1개)
리뷰어에게 주는 것 (**allowlist — 이것만**):
- 레포 경로, 동결된 diff 범위, 관련 스펙/결정 파일 경로, 리스크 포커스 한 줄(예: "저장 호환 깨짐 여부")

리뷰어에게 **절대 주지 않는 것**:
- 구현자의 추론·요약·대화 이력, "이건 이래서 안전합니다" 류 설명, 이전 리뷰 결과

리뷰어 브리프에 포함할 지시:
```
너는 이 변경을 작성하지 않았다. diff와 정본 문서에서 적합성을 처음부터 재유도하라.
작성자의 서사에 앵커링하지 마라 (애초에 받지 않았다).
추가로, 기존 테스트와 동일하지 않은 실행 가능한 probe를 서로 다른 범주에서 2개 이상 설계·실행하라.
범주: boundary(경계값) / state(상태 전이 순서) / failure(실패 주입) /
      property(불변식 대량 샘플) / differential(독립 재계산과 대조).
non-mutating 명령 선호. 대상 워킹트리 수정 금지. 코드를 고치지 마라 — 판정만.
각 probe는 "명령 + 실제 출력 + 판정"으로 보고하라. 실행 못 한 probe = 실패로 보고.
```

### 3. 판정과 루프
- 리뷰어가 Fail을 찾으면: **실패한 불변식 + 최소 재현 증거만** 받아 수정한다. 통과한 probe 목록은 보지 않는다(다음 리뷰어의 시험이 오염된다).
- 수정 후 재검증은 **새 리뷰어**로 (1단계부터). 같은 리뷰어 재사용 금지.
- **2회 반복해도 수렴하지 않으면 정지하고 사용자에게 보고한다** — 구체적 질문과 함께. 무한 루프 금지.

### 4. 완료 조건 (전부 AND)
1. CLAUDE.md §3 검증 루프 전체 통과
2. 블라인드 리뷰어 verdict = pass (또는 warning뿐 — warning은 사용자에게 명시 보고 후 수용/이슈화/즉시 수정 중 하나로 처리)
3. probe 전원 통과 + 동결 스냅샷 불변

## 합리화 방지
| 유혹 | 규율 |
|---|---|
| "내가 방금 검토했으니 리뷰어는 형식적으로" | 리뷰어에게 결론을 흘리는 순간 이 스킬은 무의미해진다. allowlist 엄수. |
| "probe는 기존 테스트로 갈음" | late-bound probe의 존재 이유가 "구현자가 몰랐던 시험"이다. 기존 테스트와 동일 금지. |
| "사소한 마이그레이션이니 생략" | §2 목록이 위험 구역이라 하면 위험 구역이다. 생략은 사용자 승인으로만. |
