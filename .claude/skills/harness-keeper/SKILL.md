# harness-keeper — 하네스 정원 관리

**전제**: 하네스는 실패 기록으로 자라지만, 방치하면 changelog가 헌법을 삼킨다. math_mon의 실사고: CLAUDE.md 5.8만 토큰(컨텍스트 29% 선소모), 기준선 3중 모순, 존재하지 않는 훅 서술.

## 점검 항목 (순서대로)

1. **이력 분리**: CLAUDE.md에서 날짜 달린 서사·개정 경위·"옛 규칙 폐기됨" 문장을 찾아 `docs/decisions/YYYY-MM-DD-슬러그.md`로 **원문 그대로** 이동. CLAUDE.md에는 현재 유효한 결론 한 줄 + 포인터만 남긴다. 이동 전 원문 전체를 커밋해 손실 0을 보장.
2. **중복 규칙 통합**: 같은 불변식이 여러 문서에 재서술되어 있으면 정본 1곳을 정하고 나머지는 포인터로 교체. (재서술은 반드시 어긋난다 — math_mon에서 5중 복제 실증.)
3. **모순 탐지**: 결정 로그·정책 문서·CLAUDE.md 사이 값이 다른 사실(기준선 수치, 정책)을 grep으로 대조. 낡은 쪽에 `> ⚠️ SUPERSEDED by <정본>` 마킹.
4. **유령 자동화 검증**: 문서가 언급하는 훅·CI·스크립트가 **실재하는지** 확인 (`.claude/settings.json` hooks, `.github/workflows/`, `scripts/`). 없으면 문서를 고치거나 실제로 만든다.
5. **승격 후보 스캔**: "프롬프트 규칙 (승격 대기)" 목록을 훑어 테스트/훅/CI로 만들 수 있게 된 것을 승격 제안. 승격되면 문서 규칙은 "자동 강제됨"으로 이동하고 재서술을 지운다.
6. **기준선 숫자 제거**: 산문 속 테스트 수·파일 수 등 스냅샷 숫자를 스크립트 산출물 참조로 교체.
7. **README 신선도**: README가 설명하는 스택·범위·배포 방식이 현재와 일치하는지 30초 대조.

## 규율

- 이 스킬은 **삭제보다 이동·마킹을 우선**한다. 유일한 파괴적 행위는 "중복 재서술 제거"뿐이며, 그것도 정본이 확정된 뒤에만.
- 정리 결과는 커밋 1개로 — 코드 변경과 절대 섞지 않는다.
- 대량 원문 이동은 기계적 작업이다 — 값싼 서브에이전트에 위임 가능(원문 그대로, 요약 금지 지시 필수). 검수·커밋은 메인.
