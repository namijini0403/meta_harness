# 하네스 초기 설치 (init-harness) v2

meta_harness 스타터킷을 실제 프로젝트 하네스로 전환한다. **목표: `{{...}}` 플레이스홀더 0, 안 쓰는 팩 0, 검증 명령 실동작 확인, 사용자 승인.**

**사용자는 코딩 초보일 수 있다.** 질문은 쉬운 말로, 꼭 필요한 것만, 한 번에 하나씩. "불변식이 뭔가요?" 같은 용어 질문 금지 — "이게 바뀌면 다른 것도 같이 바뀌어야 하나요?", "절대 잃어버리면 안 되는 데이터가 있나요?"로 번역해 묻는다.

## 0. 설치 유형 판별

- **새 프로젝트**: 킷이 곧 루트 → 1번부터.
- **기존 프로젝트 도입(레트로핏)**: 기존 `README.md`·`CLAUDE.md` **덮어쓰기 금지** — 기존 CLAUDE.md가 있으면 실전 기록이므로 킷의 절 구조와 대조해 빠진 절만 병합. `.claude/settings.json`은 permissions만 병합. 기존 문서는 정본이 아니라 참고자료다 — 낡았을 수 있으니 코드와 대조 후 반영.

## 1. 조사 먼저 (물어볼 것을 최소로 줄인다)

- 스택·구조: package.json / 빌드 설정 / 디렉터리 구조 → 머리말 초안.
- 검증 명령: 기존 test/build/typecheck 스크립트를 **실제 실행**해 동작 확인 → §3 초안. 테스트 수 = 기준선 초기값.
- git 로그·기존 문서에서 정체성·진행 중 작업 파악.
- **위험 표면 스캔**: DB/스키마 파일, 인증 코드, .env·비밀값, 배포 설정, 학생·개인정보 필드의 존재 여부 → §1 라우팅 표와 팩 선택의 근거.

## 2. 질문 규칙 (Dryforge 4분면 — 코드로 아는 것과 위험한 것을 구분)

| 코드로 유추 가능? | 틀리면 위험? | 행동 |
|---|---|---|
| 예 | 아니오 | 스스로 채우고, 마지막 요약에서 한 줄 확인만 |
| 예 | **예** | 유추 결과를 제시하고 **깊게 확인** ("코드를 보니 ○○인 것 같은데, 맞나요? 이게 틀리면 △△가 깨집니다") |
| 아니오 | **예** | **깊게 묻는다** (비즈니스 규칙·보안 정책·절대 잃으면 안 되는 데이터·이미 내려진 결정) |
| 아니오 | 아니오 | 합리적 기본값 적용, 질문 생략 |

전형적 필수 질문 (쉬운 말 버전):
1. "이 앱은 한 줄로 뭐라고 소개하면 될까요? 앞으로 어디까지 키우실 생각인가요?"
2. "절대 잃어버리거나 깨지면 안 되는 데이터·규칙이 있나요?" (→ §2 위험 구역·§3 불변식)
3. "이미 정해서 바꾸면 안 되는 결정이 있나요?" (→ §4 불변 결정)
4. 커밋·배포 규약은 조사로 유추하고 확인만.

## 3. 조립

1. CLAUDE.md 플레이스홀더 전부 채움 (해당 없는 절은 삭제 — 빈 절 금지).
2. **팩 선택은 조사 근거로 스스로 결정**하고 사용자에게 결과만 요약 확인: DB·사용자 데이터 발견 → db-analytics / 민감 도메인(학생·의료 등) → security-privacy / 브라우저 앱·자동 배포 → e2e-deploy / 콘텐츠 대량 생산 → content-verification / **대규모 병렬 에이전트 운용 계획이 명시적으로 있을 때만** → orchestration. 선택된 팩은 `INSTALL.md` 절차 실행, 미선택 팩은 폴더째 삭제.
   (기본 스킬 safe-db·auth-basics·secrets-basics·deploy-check·student-privacy·risk-review·debug·tdd·verify는 팩이 아니라 **항상 유지** — 필요할 때만 로드되므로 비용이 없다. 단 학생·아동 사용자가 전혀 없는 프로젝트면 student-privacy는 삭제 가능.)
3. `docs/decisions-log-template.md` → `docs/decisions-log.md` 복사 후 §2 문답의 결정 기록.
4. 킷 메타 정리: 새 프로젝트면 README를 프로젝트 소개로 교체, HARNESS.md는 docs/로 이동 또는 삭제(원본은 repo).

## 4. 설치 검증 (완료 선언 전)

- [ ] `node scripts/check-placeholders.mjs` → 0건
- [ ] CLAUDE.md §3 명령을 **실제 실행**해 전부 동작 (안 도는 명령을 규약에 박으면 첫 커밋부터 하네스 불신)
- [ ] 참조 무결성: CLAUDE.md가 가리키는 파일·스킬 전부 존재 (없는 자동화를 있다고 쓰지 않기)
- [ ] 사용자에게 완성본을 **쉬운 말로 요약 보고** 후 승인 → 첫 커밋
- [ ] 이 스킬 폴더(`.claude/skills/init-harness/`) 삭제 (일회용)
