# 배포와 배포 검증 (deploy-check)

대상 독자는 AI 모델이다. 사용자는 초보 교사이며 첫 배포 경험이 없을 수 있다. 이 스킬은 모델이 "명령이 끝남"과 "실제로 동작함"을 구분하도록 지시하는 문서다.

## 절차

1. **첫 배포는 관리형 플랫폼 권장**: Railway, Vercel, Render 등 관리형 플랫폼을 우선 제안한다. 직접 서버(VPS 등)를 구축·운영하는 방식은 초보 사용자에게 유지보수 부담이 너무 크므로, 사용자가 명시적으로 원하지 않는 한 권하지 않는다.
2. **배포 전 점검**:
   - secrets-basics 스킬 절차로 키 하드코딩·`.env` 노출 여부를 확인한다.
   - 이번 배포에 기존 인증·DB 구조에 영향을 주는 변경이 섞여 있으면, auth-basics/safe-db 스킬의 승인 절차를 먼저 거쳤는지 확인한다.
   - 배포 대상이 처음 공개되는 것이라면 학생 데이터 노출 여부(student-privacy 스킬 6번)도 함께 점검한다.
3. **"배포 명령 성공" ≠ "배포 성공"**: 빌드/배포 명령이 에러 없이 끝났다고 완료로 보고하지 않는다. 반드시 다음을 실제로 수행한다.
   - 실제 라이브 URL에 접속한다.
   - 핵심 기능 하나 이상을 실제로 조작(버튼 클릭, 폼 입력 등)해 정상 동작하는지 확인한다.
   - 캐시 때문에 구버전이 보일 수 있으므로 강력 새로고침이나 시크릿창으로 최신 배포본인지 확인한다.
4. **실패 시 롤백 경로 확보**: 배포 전에 이전 정상 버전으로 되돌릴 방법(플랫폼의 "이전 배포로 되돌리기" 기능 등)이 있는지 미리 확인해둔다. 없으면 배포 전에 이 위험을 사용자에게 알린다.
5. **자동 배포 여부 상기**: 프로젝트에 main 브랜치 push 시 자동 배포가 걸려 있으면, 이후의 모든 push가 곧 배포임을 사용자에게 짧게 상기시킨다. 특히 아직 검증되지 않은 변경을 push하려는 상황에서는 반드시 미리 알린다.
6. **완료 보고 형식**: 완료로 보고할 때는 반드시 (a) 라이브 URL과 (b) 실제로 무엇을 조작해서 확인했는지를 함께 적는다. 둘 중 하나라도 없으면 "완료"가 아니라 "배포 시도" 또는 "배포됨, 확인 필요"로 보고한다.

## 흔한 실수 사례

- "빌드가 성공했다는 로그를 봤으니 배포 완료로 보고"는 3번 위반이다. 빌드 성공과 실제 서비스 정상 동작은 별개다.
- 환경 변수를 배포 플랫폼에 등록하는 것을 잊고 배포하면 앱이 켜지긴 해도 기능이 죽어 있을 수 있다 — 2번의 secrets-basics 점검을 건너뛰지 않는다.
- "예전에 한 번 확인했으니 이번 배포도 같은 결과일 것"이라는 가정은 하지 않는다. 매 배포마다 3번을 다시 수행한다.
- 도메인을 새로 연결하거나 플랫폼을 바꾸는 배포는 기존 링크가 끊길 수 있다 — 사용자가 이미 공유한 URL이 있다면 영향을 먼저 알린다.
- 무료 플랜의 리소스 제한(슬립 모드, 트래픽 한도)으로 인해 처음 접속이 느리거나 실패할 수 있다. 접속 확인 시 이런 특성도 함께 안내한다.

## 완료 전 체크리스트

- [ ] secrets-basics 점검(키 하드코딩·env 노출)을 마쳤는가.
- [ ] 위험 등급 DB/인증 변경이 섞여 있다면 별도 승인을 받았는가.
- [ ] 실제 라이브 URL에 접속해 핵심 기능을 조작해봤는가.
- [ ] 캐시로 구버전이 보이지 않는지 확인했는가.
- [ ] 롤백 경로가 있는가, 없다면 사용자에게 알렸는가.

## 다른 스킬과의 관계

- 배포 직전 항상 secrets-basics 점검을 먼저 수행한다.
- DB·인증 변경이 이번 배포에 포함되면 safe-db·auth-basics의 승인 절차가 이미 끝났는지 확인한다.
- 학생 데이터가 노출되는 화면이 있으면 student-privacy 6번(비로그인 접속 확인)을 함께 수행한다.

## 사용자에게 말할 때

- "빌드", "배포 파이프라인" 대신 "지금 인터넷에 올리는 작업"처럼 풀어 말한다.
- 확인을 마친 뒤에는 "이 주소로 들어가서 ○○ 버튼을 눌러보면 실제로 동작하는 걸 볼 수 있어요"처럼 사용자가 스스로도 확인할 수 있는 방법을 함께 알려준다.
- 롤백이 필요한 상황이면 "예전 버전으로 잠깐 되돌릴게요, 몇 분 안 걸려요"처럼 불안을 줄이는 말투로 설명한다.

## 합리화 방지

| 유혹 | 규율 |
|---|---|
| "배포 명령이 에러 없이 끝났으니 완료" | 실제 URL 접속 + 기능 조작 확인 전엔 미완료 (3번). |
| "예전에 확인했으니 이번에도 될 것" | 매 배포마다 캐시·최신본 여부 재확인 (3번). |
| "급하니 롤백 경로는 나중에" | 배포 전에 확보 (4번). |
| "코드만 push했지 배포라고 말 안 했다" | 자동 배포면 push=배포임을 항상 상기 (5번). |
